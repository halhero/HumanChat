# 第八步：真实语义索引与派生数据同步

## 1. 本步解决什么

关键词检索无法理解“先说结论”和“先给判断”的语义联系。因此本步引入真实 embedding 接口，而不是用固定向量冒充语义检索。主记录仍由现有 JSON/LangGraph Store 保存，向量只是可重建的检索投影，不是第二份权威记忆。

## 2. 实际修改

- `human_chat/memory/index.py`：新增 `MemoryView`、`memory_views`、`MemoryIndex` 和 `create_embeddings`。
- `memory/service.py`：所有真实写入经过 `_persist`；索引挂接后收到变更通知，删除同步清除索引快照里的正文。
- `config.py`：增加 embedding 模型、地址、独立密钥配置。空地址/密钥沿用现有模型服务，不将真实凭据写入代码。
- `requirements.txt`：声明向量库所需 numpy；`.gitignore` 排除本轮隔离验证目录。

`InMemoryVectorStore` 是 LangChain 的向量存储实现，负责相似度计算和快照读写。这里不重新实现余弦相似度。适配器管理记录版本、同步和删除，这些是项目业务语义，不是向量库自动负责的事。选择它是因为目前是单进程、小规模项目；没有为了检索强制迁移数据库。

## 3. 数据流和关键代码

```text
主记录 inventory -> 当前/历史 MemoryView -> 仅对新正文请求 embedding
                -> LangChain 向量存储 -> 原子替换索引快照
查询 -> query embedding -> LangChain 相似度 -> 记录ID/父版本
```

索引条目包含父记录版本。后续读取必须回到主记录校验，不能直接相信快照中的旧正文。历史、撤销、过期状态也明确区分，不能一律视为当前事实。

`sync` 在网络请求前记录 generation；写入或删除会递增 generation。如果 embedding 很慢，在这期间发生删除，旧同步结果会被丢弃。网络调用不占主存储锁。相同正文可复用已存向量，避免仅证据变化就重复付费。

快照先写临时文件，再替换正式文件。更换 embedding 配置后旧向量清空重建，避免不同向量空间混用。这里是可重建索引，不改动主记录。

默认模型 `text-embedding-v4`，批次限制为10，关闭 OpenAI token-array 输入转换，使用字符串和 float 输出。参数依据[百炼官方说明](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api)。地址仍可配置，不强制覆盖用户现有可用端点。

## 4. 验证

执行 `python -m pytest tests/test_memory_index.py -q -p no:cacheprovider --basetemp .validation-step08-20261015`：1项通过。验证重开快照不重复生成向量、删除清除正文、慢同步不能复活已删除数据。使用明确标注的测试 embedding，不代表真实语义精度。首次默认临时目录遭系统权限拒绝，改用专用隔离目录后通过，未清理用户目录。

## 5. 还未做什么

本步只交付索引能力，还没有替换 Graph 的旧读取流程。第九步补混合召回，第十一步补任务适用性判断；第十四步统一接入应用资源和后台同步。生产配置和真实百炼请求在最终集成时验证。该快照适合单进程，不宣称支持多个应用进程同时写入。
