# 全项目运行验证阶段一：接口兼容与数据边界修复

日期：2026-10-10。本文记录真实运行发现的问题和第一批已验证修复；不代表整个项目已完成验收。

## 1. 本阶段做什么，为什么要做

项目经过多轮框架化和前后端改造，已有单元测试只能证明被测试的局部行为。必须把实际服务、持久化层和浏览器连接起来，确认默认配置在当前机器上真的可用。

本阶段没有重置数据库、删除用户记忆或重写旧功能。所有带写入的运行验证使用 `data/pytest-tmp-e2e-20261010/` 下的独立会话、JSON 记忆和 SQLite checkpoint。现有未提交的 `AGENTS.md`、`docs/`、`.idea/.name` 均保留。真实密钥没有写入代码或文档。

## 2. 基线验证及发现的问题

### 2.1 pytest 误收集课程示例

在项目根执行 `python -m pytest` 时，pytest 递归发现了课程导出中的同名示例测试，产生 27 个 `import file mismatch` 收集错误。单独执行 `python -m pytest tests` 则原有 30 项业务测试全部通过。

根因不是业务测试失败，也不是缓存需要删除，而是正式测试与课程参考代码没有定义清楚的收集边界。新增 `pytest.ini`，通过 `testpaths = tests` 指定项目默认业务测试位置。不删除或禁用任何原有业务测试，也不改课程文件。课程包仍可以在对应学习任务中显式独立运行。

### 2.2 STT 默认接口与百炼密钥不匹配

旧默认是 `whisper-1`，空 STT 地址使 OpenAI SDK 请求 OpenAI 的 `/audio/transcriptions`。使用项目现有百炼密钥时，该请求实际收到 401，项目接口返回 503。

百炼 Qwen ASR 的兼容协议是 `/chat/completions`，以 `input_audio` 传入音频。仅把 Whisper 的模型名换成 Qwen 并不能修复协议差异。

### 2.3 自动记忆提取表面成功、实际失效

聊天能返回答案，但真实百炼请求在提取记忆时收到 400：当前结构化输出默认路径产生了需要 JSON 提示条件的 `response_format` 请求，而现有提示词不满足要求。Graph 捕获该异常后继续结束，浏览器看到聊天成功，却没有记忆确认弹窗。

修复不能通过关闭提取、假装没有候选或隐藏日志实现。明确指定 `with_structured_output(..., method="function_calling")`，沿用 LangChain 的 Pydantic schema 解析，并使用项目模型已经具备的工具调用能力。

### 2.4 Store 默认分页导致记忆丢失和去重失效

在真实 `InMemoryStore` 中连续写入 15 条，`load()` 只返回 10 条，重复添加第 15 条还会成功。

根因是 `BaseStore.search` 默认 `limit=10`。它还执行命名空间前缀匹配，不能直接视为当前命名空间的全部条目。Repository 改为按 100 条分页，直到读取结束，并过滤为精确命名空间。Service 的去重和提示构造不需要另写分页逻辑。

### 2.5 本地工具没有保护配置与运行数据

使用临时目录内的假密钥文件验证，旧 `read_project_file` 和 `search_project_text` 都能返回 `.env` 内容。仅限制“不能超出项目目录”并不足够：密钥和私人会话就在项目目录里。

统一收紧列举、读取、搜索三个入口：禁止真实 `.env*`、MCP 实际配置、私钥、数据库及 `data/`；保留 `.env.example`；禁止越界路径与解析后越界的文件链接。遍历改用 `os.walk(..., followlinks=False)`，提前剪枝 `node_modules`、虚拟环境、构建输出和内部目录，避免搜索无意义依赖。直接读取文本限制到所需字符数，而不是先读完整大文件。

### 2.6 语音错误日志包含供应商异常正文

旧接口使用 `exc_info=True` 输出整个 SDK 异常链，供应商错误可能含密钥片段或请求数据。改为仅记录服务边界已经清洗过的错误消息。HTTP 错误码和公共错误结构不变，不把失败变成成功。

## 3. 实现位置与设计意义

| 文件 | 修改 | 为什么放在这里 |
| --- | --- | --- |
| `human_chat/config.py` | 明确 `stt_provider`，默认百炼/Qwen；计算有效上传上限 | 在配置边界区分请求协议，拒绝未知 provider |
| `human_chat/voice/stt.py` | 增加 `DashScopeSttService`；共享 SDK 客户端生命周期 | 不让 HTTP 路由了解供应商音频协议；保留 OpenAI adapter |
| `human_chat/voice/resources.py` | 根据 provider 组合 STT 实现 | 上层仍只调用 `SpeechToTextService.transcribe` |
| `human_chat/api/routes/voice.py` | 返回并执行相同有效上传限制；安全记录预期错误 | 前端显示的限制与后端执行保持一致 |
| `human_chat/memory_extractor.py` | 明确结构化输出方法 | 继续依赖框架，不手写模型 JSON 提取器 |
| `human_chat/memory_repository.py` | Store 全量分页与精确 namespace | 修复存储适配的根因，不在 Service/Graph 打补丁 |
| `human_chat/tools.py` | 三入口统一文件安全边界和剪枝遍历 | 防止任何入口绕过保密限制 |
| `pytest.ini` | 正式测试收集边界 | 分离产品回归与教材参考代码 |
| `.env.example`、`README.md` | 更新 STT provider 配置说明 | 默认示例必须与当前可用实现一致 |
| 原有测试文件 | 补充分页、namespace、provider、敏感文件回归断言 | 没有新增独立测试文件，也没有放宽原有断言 |

百炼内联音频采用 Base64：每 3 字节约变成 4 字节。服务有输入大小限制，因此应用对百炼采用不超过 7 MiB 的上传上限，为编码与 data URL 留余量；用户设置更低限制时仍遵守低值。OpenAI provider 保留其原上传上限。内存上传不要求把音频发布到公网文件服务。
