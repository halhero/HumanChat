# 误删功能修复阶段五：语音联调与本地代理加固修改记录

## 1. 本阶段目标

前四阶段已经恢复语音与长期记忆功能。本阶段不增加新的产品模块，而是针对真实运行联调
中发现的问题做最后加固：

1. 本地 STT/TTS 服务地址绕过系统 HTTP 代理；
2. 远程语音供应商继续遵守用户配置的代理环境；
3. TTS 响应必须确实是音频，不能把 JSON 或 HTML 错误页交给浏览器播放；
4. 重新执行 Python、API、测试、TypeScript 和生产构建检查；
5. 确认每个修复阶段都已形成独立提交并推送。

## 2. 联调发现了什么问题

项目默认 TTS 地址是：

```text
http://127.0.0.1:9880
```

在当前开发环境中存在系统代理配置。`httpx.Client()` 默认使用 `trust_env=True`，会读取
`HTTP_PROXY`、`HTTPS_PROXY` 等环境变量。实际联调日志显示，对 `127.0.0.1:9880` 的探测
被送入代理并返回 HTTP 502。

这会产生错误行为：即使 GPT-SoVITS 已在本机后台运行，HumanChat 也可能因为代理没有把
回环请求正确转发，而认为服务不可用。它直接违背了本次修复最重要的需求：

```text
tts_auto_start=false + 后台服务已运行 -> 直接复用
```

## 3. 为什么不能简单关闭所有代理

语音服务不一定都在本机。项目允许：

- 本地 GPT-SoVITS；
- 本地 OpenAI 兼容 STT；
- 内网服务；
- 公网云语音服务。

如果所有语音 Client 都统一设置 `trust_env=False`，需要代理才能访问公网供应商的用户会
受到影响。因此代理策略必须根据目标 URL 决定，而不是做全局开关。

## 4. 回环地址识别

新增 `human_chat/voice/http.py`，公开内部辅助函数：

```python
should_trust_environment_proxy(url: str) -> bool
```

它使用标准库：

```python
urlparse(url).hostname
ip_address(hostname).is_loopback
```

识别以下本地回环形式：

```text
localhost
127.0.0.1 以及整个 IPv4 loopback 范围
::1
```

返回规则：

```text
回环地址 -> False，不读取环境代理
远程域名或远程 IP -> True，保留环境代理
无法解析的主机 -> True，采用 httpx 默认兼容行为
```

使用 `ipaddress` 而不是只比较字符串 `127.0.0.1`，可以正确覆盖其他合法 loopback 地址，
也能处理 IPv6。

## 5. TTS Client 调整

`GptSoVitsTtsService` 创建连接池时现在使用：

```python
httpx.Client(
    timeout=timeout_seconds,
    trust_env=should_trust_environment_proxy(service_url),
)
```

因此默认本地 GPT-SoVITS 不经过代理。若用户把 `TTS_SERVICE_URL` 配置为远程域名，Client
仍会读取标准代理环境，不会破坏企业网络或受控出口环境。

探测请求和真正的 `/tts` 请求共享同一个 Client，所以两条路径不会出现“一条绕过代理、
另一条仍走代理”的不一致。

## 6. STT Client 调整

`OpenAICompatibleSttService` 的 `base_url` 为空时，仍使用 OpenAI SDK 默认客户端和默认
代理策略。

只有显式配置了本地回环 `STT_BASE_URL` 时，才向 OpenAI SDK 注入：

```python
httpx.Client(trust_env=False)
```

OpenAI Client 的 `close()` 会关闭注入的底层 HTTPX Client，因此现有 VoiceResource 清理
流程仍然完整，不需要维护第二份连接池引用。

## 7. 为什么校验 TTS Content-Type

HTTP 200 只能说明服务器返回了成功状态，不能保证 Body 是音频。某些代理、网关或包装
服务可能错误地以 200 返回：

- JSON 错误对象；
- HTML 登录页；
- 文本告警。

如果后端直接把这些字节标成音频，浏览器只会报告含糊的“播放失败”，真正的服务错误被
隐藏。

新的处理规则是：

```text
audio/*                    -> 保留实际 media type
application/octet-stream  -> 按 GPT-SoVITS 常见 WAV 响应处理为 audio/wav
其他类型                   -> SpeechSynthesisError
```

空 Body 的校验仍然保留。这样返回给 `/voice/speech` 的数据同时满足“非空”和“类型合理”
两个条件。

## 8. 与 `tts_auto_start` 的关系

代理修复没有改变进程所有权规则：

- `auto_start=false` 时不在应用启动阶段探测或创建进程；
- 用户调用能力查询或语音合成时，回环请求直接访问本机服务；
- `auto_start=true` 时先绕过代理探测本地服务；
- 已有服务可用时不创建进程；
- 只有 HumanChat 自己创建的进程才会在退出时停止。

因此配置开关仍然只控制“谁启动进程”，不会重新退化为 TTS 功能总开关。

## 10. 验证结果

本阶段完成前执行：

```powershell
git diff --check
python -m compileall -q human_chat
python -m pytest -q --basetemp=data/pytest-tmp-final -p no:cacheprovider
pnpm build
```

结果：

- Python 模块编译通过；
- 现有测试 `30 passed`；
- OpenAPI 所需语音和记忆路径全部存在；
- TypeScript 编译和 Vite production build 通过；
- `git diff --check` 没有发现空白错误。

使用真实 FastAPI 进程读取健康、语音能力和记忆列表，结果为：

```text
status        = ok
stt_enabled   = true
tts_enabled   = true
tts_available = false
memory_count  = 0
```

`tts_available=false` 符合当前机器 9880 端口没有运行 GPT-SoVITS 的实际状态；它不再是由
系统代理返回 502 造成的误判，也不影响 STT、文本聊天或记忆管理。

另外启动了一个只绑定 `127.0.0.1:9881` 的临时 HTTP 服务，验证：

- `localhost`、`127.0.0.1` 和 `::1` 的策略返回“不使用环境代理”；
- 公网 URL 策略返回“保留环境代理”；
- TTS 可用性探测返回 `True`，服务日志收到真实 `GET /`，不再得到系统代理的 502。

代理策略结果为：

```text
localhost             -> trust_env=False
127.0.0.1             -> trust_env=False
::1                   -> trust_env=False
https://api.example.com -> trust_env=True
```

使用 HTTPX MockTransport 检查 TTS 响应类型，结果为：

```text
audio/wav                -> 接受为 audio/wav
application/octet-stream -> 接受并规范为 audio/wav
application/json         -> 拒绝并抛出 SpeechSynthesisError
```

临时回环 HTTP 服务在验证结束后已经停止，没有加入项目文件或长期运行资源。

最后用生产构建产物启动 FastAPI 并实际打开页面，确认语音文件、麦克风、自动朗读和长期
记忆入口均出现。长期记忆对话框在空数据状态下布局完整，标题、关闭按钮、输入框和添加
按钮没有重叠；检查过程中没有写入或删除用户记忆。

## 11. 整体修复边界

本轮最终保留并恢复的是：

- 角色 TTS 配置；
- STT/TTS 供应商调用能力；
- 可选本地 GPT-SoVITS 生命周期；
- 浏览器录音、音频文件转写和浏览器播放；
- 自动朗读与按消息朗读；
- 长期记忆查看、添加和删除。

仍然没有恢复：

- 服务器 `sounddevice` 麦克风录音；
- 服务器 `simpleaudio` 播放；
- 固定共享 WAV 临时文件；
- Graph 内强制 TTS 节点；
- 旧 CLI Runtime 与命令循环。

这确保恢复的是产品能力，而不是把已经淘汰的运行架构重新带回来。
