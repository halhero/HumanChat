## 3. 唯一文本命中为何保留

全局搜索唯一命中是测试中的：

```text
memory.search.sqlite
```

它是现有 SQLite sidecar 的物理文件名，不是 Python 的 `memory.search` 属性，也不是旧模块导入。

本轮明确禁止数据库结构变化，并且没有索引文件迁移需求。擅自把已有 `.search.sqlite` 改成新文件名会导致程序改用一个新的空索引文件，使旧索引文件被遗留。因此本轮保留物理文件名，同时把代码层术语统一为 index store。

## 5. 最终依赖关系

最终结构为：

```text
MemoryRepository
  └─ 完整、权威的 MemoryItem

MemoryIndexStore
  ├─ 实现 MemoryIndexWriter
  └─ 实现 MemoryIndexReader

LongTermMemoryService
  ├─ 依赖 MemoryRepository
  └─ 只声明依赖 MemoryIndexWriter

MemoryRetriever
  └─ 只声明依赖 MemoryIndexReader

MemoryResource
  ├─ 暴露 service
  └─ 暴露 retriever
```

应用层不再接触 repository 或 index store。

## 6. request 的最终读取路径

已选记忆进入实际模型请求时使用：

```text
reference.parent_id
  ↓
service.get_items(parent_ids)
  ↓
读取少量 MemoryItem
  ↓
从 entry.id 解析 version
  ↓
直接选择 MemoryItem 或 MemoryItem.history
  ↓
重新检查 parent_version 和有效状态
  ↓
装入 prompt
```

这条路径不导入 index store，不生成索引条目，也不执行搜索。

## 7. 索引写入与召回的最终路径

写入路径：

```text
LongTermMemoryService.apply()
  ↓
repository.upsert_item()
  ↓
MemoryIndexWriter.upsert_item()
```

召回路径：

```text
MemoryRetriever
  ├─ search_lexical()
  ├─ search_semantic()
  ├─ search_identity()
  └─ current_documents()
```

SQLite 和 PostgreSQL 仍由一个具体 store 同时提供读写能力，没有复制索引实例。

## 9. 本轮明确未修改的内容

遵循任务范围，本轮没有修改：

- `current_documents()` 的全量轻量索引读取；
- `task_background_catalog`；
- BM25、向量检索或 RRF 算法；
- 召回窗口、排序和 limit；
- SQLite/PostgreSQL 数据库 schema；
- mutation、formation、版本历史和 prompt 业务语义；
- `.search.sqlite` 物理文件名。

## 10. 剩余验证限制

SQLite FTS5 和 sqlite-vec 路径由现有定向测试真实执行。PostgreSQL 类型和资源装配能够导入，但当前没有外部 PostgreSQL + pgvector 服务，因此本轮没有声明 PostgreSQL 真实连接和 HNSW 查询已通过。

`current_documents()` 仍会读取全部当前轻量索引条目。该问题按本轮要求只记录，不增加 limit、不改排序、不移除 catalog 通道。
