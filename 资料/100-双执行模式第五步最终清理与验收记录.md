# 双执行模式第五步：最终清理与验收记录

日期：2026-11-21。

## 1. 本轮最终完成状态

HumanChat 现在已经拥有两条由 Triage 唯一决定的执行路径：

```text
react
plan_execute
```

`react` 由独立的官方 `create_agent` 负责一次请求内的模型与工具循环，结果直接进入 `finalize_reply`。

`plan_execute` 由父 `StateGraph` 负责确定的阶段编排，由另一个独立 `create_agent` 每次只执行一个 `PlanStep`，最后统一汇总。

两个 Agent 共用当前项目工具注册表，但具有不同的输出契约和 middleware。它们不共享跨步骤内部 messages，也不配置独立 checkpointer/store。

## 2. 最终数据流

### ReAct

```text
原始用户消息
  + resolved_request
  + 有界近期历史
  + memory_context
        |
        v
react_agent
        |
        v
assistant_text
        |
        v
finalize_reply
```

### Plan-Execute

```text
resolved_request + memory_context + 工具能力摘要
        |
        v
ExecutionPlan
        |
        v
PlanStep -> StepResultSubmission -> StepExecutionRecord
        |                              |
        +----------- Replan <---------+
                       |
                       v
               summarize_plan_result
                       |
                       v
                assistant_text
                       |
                       v
                finalize_reply
```

原始用户消息始终是事实来源，`resolved_request` 仍然只是本回合派生语义。Plan 的中间步骤和工具消息不会进入最终聊天历史或长期记忆证据。

## 3. 三类中断已完整贯通

| kind | 生产者 | 用户决定 | 恢复到 |
| --- | --- | --- | --- |
| `tool` | Agent HITL middleware | `approve | reject` | 同一 Agent 工具调用 |
| `user_input` | Step Agent 的 `ask_user` | `respond | stop` | 同一 `PlanStep` |
| `plan_budget` | 父 Graph `interrupt()` | `continue | continue_with_input | stop` | 计划路由或 Replan |

工具审批和 `ask_user` 使用官方 batched `decisions` 协议；计划额度使用父 Graph 的独立恢复值。转换只发生在 `ConversationService`，API route 和前端不构造 LangGraph `Command`。

## 5. 全量验收发现并修复的旧问题

第一次全量测试结果为：

```text
111 passed, 1 failed
```

唯一失败是已有 `ApiError` 被定义为：

```python
@dataclass(frozen=True)
class ApiError(Exception):
    ...
```

当 FastAPI/Starlette 处理该异常时，会按 Python 异常机制写入 `__traceback__`。冻结 dataclass 禁止该写入，因此原本应返回 404 的路由抛出 `FrozenInstanceError`。

修复只取消 `ApiError` 的 `frozen=True`，不改它的字段、处理器、错误包结构或公开协议。这是异常对象正常工作所必需的最小根因修复，不是 Plan-Execute 的新机制。

重跑原失败用例：`1 passed`。

## 8. 与实施规格的差异

业务架构、状态、路由、中断协议和前端交互没有主动偏离已确认规格。

实施层面只有两个必要说明：

1. 当前 LangChain 1.3.1 的 `HumanInTheLoopMiddleware` 不存在 `interrupt_mode` 参数，但其默认就是需要的 batched 协议，因此只省略了不存在的实参，没有升级依赖或引入兼容层。
2. 本机 `pnpm build` 中 TypeScript 7 的 JavaScript wrapper 启动原生编译器时挂起；最终直接运行同一安装包内的官方 `tsc.exe`，再执行 Vite build。未改变依赖、包管理器或构建配置。
