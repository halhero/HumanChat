# 请求装配解除索引投影依赖修改记录

日期：2026-11-11。

## 1. 本步修改范围

本步只调整回答请求装配阶段读取已选长期记忆的方式，没有修改召回算法、索引数据库、记忆形成、记忆写入、数据库表结构或 prompt 字段。

涉及文件：

- `human_chat/memory/request.py`
- `tests/test_memory_request.py`

## 2. 原来的调用关系

任务上下文判断完成后，`context_references()` 会保存已选索引条目的引用：

```text
id             = {parent_id}@{version}
parent_id      = 主记忆 ID
parent_version = 选择时主记忆的当前版本
purpose        = constraint / guidance / background / evidence / history
```

`assemble_request()` 随后按 `parent_id` 从主数据库定向读取 `MemoryItem`。但旧实现没有直接在 `MemoryItem` 中定位版本，而是再次调用 `documents_for_item()`：

```text
MemoryItem
   ↓
重新生成全部 SearchDocument
   ↓
按 reference.id 查找其中一条
   ↓
转换成 prompt 记录
```

这条路径没有再次访问索引数据库，却让请求装配依赖了索引层的数据模型和投影规则。

## 3. 为什么 request 不应依赖索引投影

主数据库和索引存储承担不同职责：

- 主数据库保存完整、权威的 `MemoryItem`，包括当前版本和历史版本。
- 索引存储保存适合全文检索、向量检索和 identity 检索的轻量投影。
- request 只负责把已经选中的权威记录装入实际模型请求。

当 request 已经持有 `parent_id` 和 `{parent_id}@{version}` 时，索引检索阶段已经结束。再次生成索引投影会造成三个问题：

1. 请求装配知道了不属于自身职责的索引结构。
2. 索引条目字段或命名变化会无端影响 prompt 装配。
3. 主记录明明已经包含所需版本，却要经过一次额外转换才能读取。

本次修改消除了这项反向依赖，但没有改变引用格式，因此索引条目 ID 仍保持：

```text
{parent_id}@{version}
```

## 4. 新的版本解析流程

`request.py` 新增内部函数 `_selected_memory_record()`。它只执行请求装配需要的工作：

```text
检查 entry.id 是否以 "{parent_id}@" 开头
   ↓
读取后缀并确认它是正整数版本
   ↓
确认主记录当前版本仍等于 parent_version
   ↓
如果选中当前版本，直接读取 MemoryItem
   ↓
如果选中历史版本，按 version 查找 MemoryItem.history
   ↓
按原字段结构生成 prompt 记录
```

这里没有加入正则、多格式兼容或旧 ID fallback。内部引用遵循项目当前明确契约，必要校验只用于防止选择完成后记录发生变化，或失效内容进入 prompt。

## 5. 当前版本与历史版本如何读取

### 5.1 当前版本

当引用版本等于 `item.version` 时，直接使用 `MemoryItem` 的：

- `text`
- `assertion`
- `observed_at`
- `version`

当前版本只有在 `item.usable_now()` 为真时才可装配。这会排除：

- `deleted` 记录；
- `retracted` 记录；
- 已经过期的 active 记录。

### 5.2 历史版本

当引用版本不是当前版本时，在 `item.history` 中按 `version` 精确查找。

历史版本必须同时满足：

- 状态为 `historical`；
- 选择用途为 `history`。

因此 revoked 历史版本不能进入 prompt，普通回答也不能把历史状态误当成当前事实。

## 6. 保持不变的行为

本次修改没有改变以下行为：

1. `parent_version` 用于检测“选择后主记录已变化”。
2. 一个 bundle 中任意条目失效时，整个 bundle 都不装配。
3. 失效 bundle 仍产生 `context_changed_since_selection`。
4. critical bundle 的预算处理保持不变。
5. 历史消息预算、工具 schema 预算和输出预留保持不变。
6. 合法记录进入 prompt 的字段、值和 JSON 结构保持不变。
7. 索引条目 ID 格式保持 `{parent_id}@{version}`。

## 7. 定向测试

本步测试覆盖：

- 当前版本直接从 `MemoryItem` 正常装配；
- 历史版本直接从 `MemoryItem.history` 正常装配；
- 合法场景生成的 prompt 记录字段和值保持不变；
- ID 前缀错误和版本后缀错误时丢弃 bundle；
- 引用版本不存在时丢弃 bundle；
- `parent_version` 变化时丢弃 bundle；
- deleted、retracted、expired 当前记录不会进入 prompt；
- revoked 历史记录不会进入 prompt；
- 原有删除后重读和整请求预算测试继续通过。

## 8. 未处理事项

本步有意不处理：

- 索引类型和文件命名；
- Reader/Writer 接口拆分；
- `MemoryResource` 对底层索引对象的暴露；
- `current_documents()` 的全量轻量目录读取；
- 召回数量、排序、embedding 和 task background catalog。

这些内容不属于本步骤，后续步骤会分别处理其中已获授权的结构问题。
