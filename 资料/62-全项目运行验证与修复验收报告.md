## 3. 验证范围与真实设计

当前调用关系是：

```text
React / TypeScript / Vite
  -> FastAPI JSON API / SSE
  -> ConversationService + HumanChatApplication
  -> LangGraph / SQLite Checkpointer
  -> MemoryService / Repository / JSON 或 LangGraph Store
  -> ToolRegistry / Local Tools / MCP Adapter + Async Bridge
  -> VoiceResource / STT Adapter / GPT-SoVITS HTTP Adapter
```

Application 通过 FastAPI lifespan 拥有资源，Graph 持有执行状态，ConversationService 持有进程内 HTTP turn 状态，浏览器负责用户侧录音和播放。本轮维持这一设计，没有恢复旧 CLI、另造状态框架或删除角色语音配置。

### 4.2 第二阶段：恢复与浏览器交互

| 问题或风险 | 根因与影响 | 修复位置 |
| --- | --- | --- |
| 后端重启后旧 turn id 404，但 checkpoint 和历史存在 | HTTP 对象只存在内存，浏览器缓存 id 不能恢复审批 | Application 查询 interrupt，ConversationService 恢复，新会话活动任务接口，前端按后端状态恢复 |
| HTTP 取消与 Graph 待执行状态不一致 | 仅改 status 会留下 continuation；新增恢复能力后已取消审批可能再次出现 | `discard_pending_turn` 与取消状态收敛；已有 SQLite 用例验证不复活、不保存未批准记忆 |
| SSE 与历史的助手消息 id 不同 | 适配层另造 id，影响去重、稳定 UI 与语音关联 | Graph 明确消息 id，SSE 复用，阶段结束同步已提交历史 |
| EOF 被视为成功 | 流断连与正常完成未区分，可能造成错误成功状态 | `web/src/api.ts` 检查阶段终止事件并清理 reader |
| WebM 音频浏览器上传 415 | 操作系统标记为 `video/webm`，后端拒绝容器别名 | 上传 MIME 规范化、路由兼容支持的容器别名 |
| 实际音频能播放，结束却显示播放失败 | 清空 src 时旧错误回调还存在，资源清理触发误报 | `useVoice.ts` 先移除回调，再释放音源/object URL |
| 390px 移动视口 document 宽 425px，发送区被裁切 | Grid/Flex 最小内容宽度使长标题撑大容器 | CSS 最小列/子项约束；修复后 document 为 390px、输入区宽 366px |
| MCP 调用成功，Windows 退出出现 WinError 10038 | Proactor loop 在主线程创建、后台关闭，遗留失效的进程信号唤醒 fd | `mcp_provider.py` 在所属线程创建、运行、关闭，传递创建失败 |
| 校验日志、请求卸载和加载/转写操作存在附带风险 | 校验错误含原始 input；卸载只取消初始请求；不同阶段操作可能竞争 | 最小化日志、取消当前 controller、明确界面锁定。属于审查后的预防性补强，不把全部极端时序宣称为已复现 |

### 5.2 HTTP 与事件链路

通过临时 HTTPX 验证器访问真实监听端口，**22 项契约断言通过**：健康、会话和记忆列表、会话/活动任务/API/静态资源缺失、非法 limit、空聊天/合成文本、错误音频类型、空音频、超限音频、记忆新增/重复/稳定 id/删除/重复删除、CORS、首页不缓存、哈希资源 immutable、SPA 路由。

真实 SSE 观察到开始、进度、助手消息和完成事件；受保护 MCP 调用先出现审批事件，批准后才执行。待审批时新轮请求、无效记忆候选均返回 409。取消实际进入 cancelling/cancelled，最终活动任务接口为 null。

服务关闭与重新打开后，原 SQLite 消息仍存在，待记忆审批能以新 HTTP id 恢复。浏览器点击拒绝后继续发消息，获得正常回答，历史随后从 2 条增至 4 条。最终预览中又完成一轮简短真实回复，历史为 6 条。

### 5.3 真实外部供应商和本地模型

- 聊天：真实百炼 `qwen3.5-flash` 请求成功，不是 Fake 回复。
- 记忆：真实百炼 function calling 提取候选，浏览器确认后实际写入独立 JSON 记忆；读取/手动 CRUD 也经验证。
- TTS：在提供的 GPT-SoVITS 安装目录使用对应 `gptso` 环境，加载现有 Nanami 模型和参考音频，真实接口返回 325164 字节、32000 Hz、5.08 秒 WAV。
- STT：没有用户录音样本，使用上项生成的已知日文音频。WAV 和 WebM/Opus 都经过真实百炼 Qwen ASR，接口为 200，转写符合已知文本。最终回归直接以 `video/webm` 上传也成功。
- TTS 生命周期：复用已存在服务时 `tts_process_owned=False`，关闭 resource 不停止外部服务；冷启动时 `tts_process_owned=True`，实际合成 1.46 秒音频，退出上下文后服务停止。
- MCP：正式环境没有启用 MCP 配置。本次用临时 FastMCP stdio 服务器提供 echo 和受保护 no-op，实际创建子进程并通过官方 Adapter 发现工具。真实模型调用返回 `MCP verified: final-protocol-check`；受保护工具批准后返回 no-op 结果。它验证真实协议，但不证明用户外部服务器已接入。

## 7. 剩余风险与未验证范围

1. **真实麦克风和终端硬件**：未授权或操作真实麦克风采集，无法证明权限弹窗、设备故障和不同移动浏览器录音格式都正常。合成音频识别不能替代硬件录音验收。
2. **用户外部 MCP**：正式 `.env` 仍未启用 MCP；没有正式服务器配置。HTTP/SSE/streamable HTTP、认证、真实多个服务器竞争和外部业务副作用未验收。
3. **PostgreSQL**：未提供数据库服务和凭证。JSON/SQLite 已真实验证，InMemoryStore 已实例化验证分页；Postgres 的真实连接、迁移、连接池和事务不能宣称通过。
4. **并发部署和安全**：HTTP turn coordinator 是进程内的，当前只适合单 worker；缺少完整认证、多用户隔离、分布式会话锁、限流及公网部署安全验收。不要直接作为公网多租户服务部署。
5. **外部 TTS 安装环境**：发现安装目录内 `runtime/ffmpeg.exe` 是零字节文件，未改动外部安装包。本次使用现有 Conda FFmpeg 6.1 成功转码；当前实际推理与接口可用，但换机器/改变 PATH 后仍需确保有效 FFmpeg 和模型文件存在。非默认 TTS 监听参数、其他 API 脚本和其他 GPT-SoVITS 版本未验收。
6. **供应商和模型行为**：已证明当前 key、地域端点和模型可调用，不保证未来额度、网络、模型下线或供应商变更。模型自然语言会改变措辞，不应仅凭答复措辞断定工具是否成功。
7. **耐久和压力**：未运行长时间 soak、负载、故障注入、断电/磁盘损坏、恢复中崩溃或全平台测试。尚无“没有其他任何缺陷”的保证。
