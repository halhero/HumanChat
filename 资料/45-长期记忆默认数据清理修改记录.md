# 45 长期记忆默认数据清理修改记录

## 本次目标

本次修改删除长期记忆模块自动生成的六条演示记忆，使新的用户记忆文件从空集合开始，只保存用户手动添加或经过审核确认的真实记忆。

同时清理本地现有的 `data/memory/user_profile.json` 默认数据，避免修改初始化代码后，运行时仍继续读取已经落盘的演示内容。

## 修改前的问题

旧的 `create_default_memory()` 会自动构造以下类型的信息：

```text
用户偏好中文沟通和讲解
用户希望先查看设计再修改代码
用户正在开发 HumanChat
HumanChat 使用的技术框架
```

这些内容看起来像已经确认过的用户长期记忆，但实际只是项目开发阶段的预设样例，并非由当前用户通过记忆审核流程保存。

`JsonMemoryRepository` 在文件不存在时会调用：

```python
memory = create_default_memory()
self._save_memory(namespace, memory)
```

因此仅删除 JSON 文件并不能清理这些内容。下一次读取时，同样的六条默认记忆会被重新创建。

这会带来以下问题：

1. 用户尚未确认任何记忆，Prompt 中却已经包含个人偏好和项目事实。
2. 默认演示数据与真实长期记忆使用相同 `MemoryItem` 模型，界面无法区分其可信来源。
3. 删除文件无法完成重置，行为不符合用户直觉。
4. 如果未来切换存储后端，演示数据可能被误认为需要保留的历史数据。
5. 测试依赖演示内容数量，导致初始化策略无法独立调整。

## 修改内容

### 1. 默认记忆改为空集合

`create_default_memory()` 从预置六条 `MemoryItem` 改为：

```python
def create_default_memory() -> LongTermMemory:
    return LongTermMemory()
```

`LongTermMemory.items` 使用 Pydantic 的 `default_factory=list`，所以每次创建都会获得独立空列表，不会在不同实例之间共享可变对象。

### 2. 保留缺失文件的初始化能力

本次没有删除 `create_default_memory()`，也没有改变 `JsonMemoryRepository` 的文件初始化流程。

第一次读取不存在的记忆文件时，Repository 仍会创建合法 JSON：

```json
{
  "items": []
}
```

区别只在于初始化内容为空，不再注入业务数据。

### 3. 保留旧分类结构兼容解析

`LongTermMemory.__init__()` 对以下旧字段的兼容仍然保留：

```text
preferences
facts
notes
```

如果用户以后提供真正存在的旧格式数据，模型仍能将其转换为 `MemoryItem(source="legacy")`。本次删除的是演示种子数据，不是旧结构兼容能力。

### 4. 清理本地默认数据文件

本地 `data/memory/user_profile.json` 中的六条记录与 `create_default_memory()` 完全对应，来源均为 `default`，因此已作为无用开发残留删除。

该路径被 `.gitignore` 中的规则忽略：

```text
data/memory/*.json
```

所以文件删除只影响当前本地运行数据，不进入 Git commit，也不会删除其他开发者机器上的个人记忆文件。

### 5. 测试改为验证空初始化

记忆模型测试现在验证：

```text
两个默认 LongTermMemory 实例都为空
两个实例的 items 列表不是同一个对象
```

JSON Repository 测试现在验证首次读取会创建文件，并返回空记忆列表，不再要求默认内容非空。

## 为什么这样设计

长期记忆属于用户数据。系统可以提供数据结构和保存流程，但不应该把开发阶段的假设伪装成已经确认的个人事实。

空初始化使记忆来源可以被清楚追踪：

```text
manual                -> 用户通过命令添加
extracted_confirmed   -> Agent 提取并经用户确认
legacy                -> 真实旧结构兼容转换
```

默认构造函数只负责提供合法模型，不再负责填充产品演示内容。

## 对成熟项目的意义

1. 避免未经用户确认的信息进入系统 Prompt。
2. 新用户拥有可预测的空白记忆状态。
3. 删除记忆文件能够真正完成本地重置。
4. 默认模型构造不再与特定用户和项目事实耦合。
5. 测试验证数据结构行为，而不是依赖演示内容。
6. 为以后建立记忆来源审计和用户授权边界提供可靠基础。

## 测试覆盖

本步骤更新测试验证：

```text
默认长期记忆为空
默认实例之间不存在可变列表共享
JSON Repository 首次读取创建空记忆文件
旧 preferences、facts、notes 结构仍可解析
```
